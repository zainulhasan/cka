## 1. Why this matters

Almost everything Kubernetes gives you is text: `kubectl get` tables, container logs, kubelet journal lines, YAML manifests, certificates dumped as text. The broken thing is usually one line in a few thousand, and the tools in this lesson are how you find that line in seconds instead of scrolling.

Tasks often say "save the output to a file" (for example "save the names of all Pods that are not Running to `/opt/answer.txt`"). Treat the file as the answer: a file with one extra column, a trailing space or a missing line is a wrong answer even if you "saw" the right result on screen. (How often the exam asks for answer files is UNVERIFIED; it is advice, not an exam fact.) The Linux Foundation says the exams are "15-20 performance-based tasks" in 2 hours ([tips page](https://docs.linuxfoundation.org/tc-docs/certification/tips-cka-and-ckad), [FAQ](https://docs.linuxfoundation.org/tc-docs/certification/faq-cka-ckad-cks)), which is about 6 minutes per task. You cannot spend 3 of them hand-copying names.

In real life the same skills stop outages. A `sed -i` that matches more lines than you meant corrupts a static Pod manifest and the control plane component silently disappears. An `awk '{print $8}'` that was right yesterday prints garbage today because a Pod restarted and the table grew two extra words. Knowing why these things happen is the point of this lesson.

## 2. Concepts

### 2.1 The mental model: streams of lines, split into fields

Every tool here reads **text**, line by line, from files or from **standard input** (stdin), and writes lines to **standard output** (stdout). A **pipe** (`|`) connects the stdout of one program to the stdin of the next. The programs run at the same time; the kernel keeps a small buffer (64 KiB by default on Linux) between them. See [T1.01](../part1-linux/T1.01-bash-shell-essentials-for-exam-speed.md) for pipes, redirection, quoting and `set -o pipefail`. This lesson only uses them.

Each tool looks at the text in a different unit. Knowing the unit tells you which tool to pick.

| Tool | Unit it works on | Typical job | One-line summary |
|---|---|---|---|
| `head`, `tail`, `wc`, `less` | the whole file / line count | look, count, follow | "show me the start, the end, how many" |
| `grep` | whole **lines** | keep or drop lines | "which lines contain X" |
| `sed` | whole lines (edits inside them) | replace text, print ranges | "change X to Y" |
| `awk` | **fields** inside a line | pick columns, compare, count | "column 4 is not Running" |
| `cut`, `tr`, `column` | fields / single characters | quick column cut, clean-up, pretty print | "take column 2", "squeeze spaces" |
| `sort`, `uniq` | whole lines (or a key) | order, de-duplicate, count | "most common first" |
| `find` | **files** (names, age, size) | locate files | "logs changed in the last 5 min" |
| `xargs` | list items -> command arguments | run a command per item | "label every Pod in this list" |
| `diff` | two files | show what changed | "what did my `sed` really do" |

**Why this matters for speed.** A real answer is almost always a chain: pick the right lines (`grep`), pick the right columns (`awk`), put them in order (`sort`), count (`uniq -c`), save (`>`). You add one stage at a time and run the pipe after each stage to see the text. That habit (build left to right, look after every `|`) catches wrong columns immediately.

**Under the hood: what a pipeline really is.** The shell creates one pipe per `|`, starts every program at once, and wires stdout of the left one to stdin of the right one. If the reader is slower, the writer waits when the buffer is full. If a reader exits early (for example `head -n 1`), the writer gets a `SIGPIPE` signal and stops. The exit status of the whole pipeline is the status of the **last** program unless you set `pipefail`. Two consequences you will meet below: a failing `kubectl` at the start of a pipe does not make the pipe fail, and a program in the middle may hold output in its own buffer when it is not writing to a terminal (see `--line-buffered` in 2.3).

### 2.2 Looking at files: `less`, `head -n`, `tail -n`, `tail -f`, `wc -l`

These five answer "what is in this file, how big is it, and what is being written to it now".

| Command | What it does | Notes |
|---|---|---|
| `head -n 20 f` | first 20 lines (default 10) | `head -n -1 f` prints everything except the last line (GNU) |
| `tail -n 20 f` | last 20 lines (default 10) | `tail -n +2 f` prints from line 2 to the end. This is the classic "skip the header" |
| `tail -f f` | print the last lines, then keep printing new lines as they are appended | stops with `Ctrl+C`. Follows the open file, so it loses track after log rotation |
| `tail -F f` | same, but follows the file **name** and retries | use it on rotated logs such as `/var/log/pods/.../0.log` |
| `wc -l f` | number of lines (counts newline characters) | `wc -l < f` prints only the number. `-w` words, `-c` bytes |
| `less f` | scrollable pager | keys below |

`less` keys worth knowing: `/text` search forward, `?text` search backward, `n` / `N` next / previous match, `g` / `G` top / bottom, `&text` show only matching lines (press `&` and Enter to clear), `F` follow the end like `tail -f` (`Ctrl+C` to stop following), `-S` toggle line wrapping (useful for wide `kubectl` tables), `q` quit. `man` uses the same pager, so these keys also work when you read a man page in the exam.

Real output (a synthetic kubelet journal file, 189 lines; the generator script is in Lab 2 so you can reproduce it). In every output block, text after `<-` or in parentheses is my annotation, not program output:

```text
REAL OUTPUT (Docker)

Oct 27 10:02:02 lab-control-plane kubelet[612]: I1027 10:02:02.016714     612 kubelet.go:1005] "SyncLoop UPDATE" source="api" pods=["default/web-0"]
Oct 27 10:00:12 lab-control-plane kubelet[612]: E1027 10:00:12.001644     612 kubelet.go:1003] "Error syncing pod, skipping" err="failed to StartContainer: ImagePullBackOff" pod="default/web-0"

$ wc -l kubelet.log
189 kubelet.log

$ wc -l < kubelet.log
189

$ printf "H\na\nb\n" | tail -n +2

b
```

**`wc -l` counts newline characters, not "lines of text".** A last line without a trailing newline is not counted:

```text
REAL OUTPUT (Docker)
$ printf 'no newline at end' > nonl.txt; wc -l nonl.txt
0 nonl.txt
```

This matters when you count `kubectl` output: `k get pods` prints a header line, so `k get pods | wc -l` is one more than the number of Pods. Use `--no-headers` (`k get pods --no-headers | wc -l`) or `tail -n +2`.

**Related but different: `kubectl logs`.** `k logs -f POD` streams a container log through the API server. `tail -f /var/log/pods/...` reads the same file directly on the node, which still works when the API server is down. You use it in CKA node troubleshooting.

### 2.3 `grep`: keep the lines you want

**What it is.** `grep` reads lines and prints the ones that match a **pattern**. The pattern is a **regular expression** (regex): a small language for "text shaped like this". The name comes from the old editor command `g/re/p`.

**The problem it solves.** You have 5,000 log lines and you want the 12 that mention `ImagePullBackOff`. Without `grep` you read all of them.

Flags you must know:

| Flag | Meaning | Example (from the lab file) |
|---|---|---|
| `-i` | ignore case | `grep -i "pull image" kubelet.log` |
| `-v` | invert: print lines that do **not** match | `grep -vc " E1027 " kubelet.log` (count of non-error lines) |
| `-n` | prefix each line with its line number | `grep -n "Node not found" kubelet.log` |
| `-c` | print only the **count of matching lines** | `grep -c "Node not found" kubelet.log` |
| `-o` | print only the matching part, one match per line | `grep -Eo 'pod="[a-z0-9/-]+"' kubelet.log` |
| `-r` | search a directory recursively | `grep -rn image: /etc/kubernetes/manifests` |
| `-R` | like `-r`, but also follows symlinks (files that only point to another file) found while walking | needed for `/var/log/containers` (see 2.12) |
| `-E` | extended regex (ERE) | `grep -E 'ERROR|WARN' f` |
| `-F` | fixed string, no regex (dots are dots) | `grep -F 'a.b'` |
| `-w` / `-x` | match whole word / whole line only | `grep -w 'web-0'` |
| `-l` / `-L` | print only names of files that do / do not match | `grep -rl etcd /etc/kubernetes/manifests` |
| `-h` / `-H` | hide / force the file name prefix | `grep -rh image: dir` |
| `-q` | print nothing, only set the exit code | `grep -q ERROR f && echo found` |
| `-A N` / `-B N` / `-C N` | also print N lines **A**fter / **B**efore / around (**C**ontext) each match | next block |
| `-e PATTERN` | give the pattern explicitly (needed when it starts with `-`) | `grep -e '--etcd-servers' f` |
| `--include=GLOB` | with `-r`, only look at matching file names | `grep -r --include='*.yaml' -l etcd dir` |

**Context flags** show what happened around an error. The input is:

```text
10:00:01 starting api
10:00:02 listening on :6443
10:00:03 ERROR etcd unreachable
10:00:04 retrying in 5s
10:00:09 ERROR etcd unreachable
10:00:10 connected
```

```text
REAL OUTPUT (Docker)
$ grep -A1 ERROR ctx.log
10:00:03 ERROR etcd unreachable
10:00:04 retrying in 5s
10:00:09 ERROR etcd unreachable
10:00:10 connected

$ grep -B1 ERROR ctx.log
10:00:02 listening on :6443
10:00:03 ERROR etcd unreachable
10:00:04 retrying in 5s
10:00:09 ERROR etcd unreachable

$ grep -C1 "retrying" ctx.log
10:00:03 ERROR etcd unreachable
10:00:04 retrying in 5s
10:00:09 ERROR etcd unreachable

$ grep -n -A1 ERROR ctx.log
3:10:00:03 ERROR etcd unreachable
4-10:00:04 retrying in 5s
5:10:00:09 ERROR etcd unreachable
6-10:00:10 connected
```

With `-n` and context, a `:` after the line number marks a **matching** line and a `-` marks a **context** line. When two context windows touch, `grep` merges them; when they do not, it prints a `--` line between groups.

**`-c` counts lines, `-o | wc -l` counts matches.** A line with two matches counts once for `-c` and twice for `-o | wc -l`. In the lab file every line has one match, so both print 8:

```text
REAL OUTPUT (Docker)
$ grep -c "Node not found" kubelet.log; grep -o "Node not found" kubelet.log | wc -l
8
8
```

**Basic vs extended regex.** `grep` has two dialects. Basic (BRE, the default) treats `+ ? | ( ) { }` as ordinary characters unless you put a backslash in front (a GNU extension). Extended (ERE, `-E`) is the other way round. Almost nobody remembers which is which, so the rule is: **use `-E` and write the regex the way you would expect**.

| Meaning | BRE (default) | ERE (`-E`) |
|---|---|---|
| one or more `a` | `a\+` | `a+` |
| zero or one `a` | `a\?` | `a?` |
| `ERROR` or `WARN` | `ERROR\|WARN` | `ERROR|WARN` |
| group | `\(ab\)` | `(ab)` |
| 2 to 3 digits | `[0-9]\{2,3\}` | `[0-9]{2,3}` |
| a literal `+` | `+` | `\+` |
| any single character | `.` | `.` |
| literal dot | `\.` | `\.` |
| start / end of line | `^` / `$` | `^` / `$` |
| any of / none of | `[abc]` / `[^abc]` | `[abc]` / `[^abc]` |

```text
REAL OUTPUT (Docker)
$ echo 'a+b a.b aab' > re.txt
$ grep -o "a+b" re.txt; grep -oE "a+b" re.txt; grep -o "a\+b" re.txt; grep -o "a.b" re.txt; grep -oF "a.b" re.txt
a+b          <- BRE: + is a plain plus sign
aab          <- ERE: a+b means "one or more a, then b"
aab          <- BRE with \+: same as ERE a+b
a+b          <- BRE: . matches any char, so a+b, a.b and aab all match
a.b
aab
a.b          <- -F: only the literal text a.b
```

(The output lines above are what the commands print, in order. The `<-` notes are added by hand.)

```text
REAL OUTPUT (Docker)
$ printf 'ERROR one\nWARN two\nINFO three\nerror four\n' > lv.txt
$ grep -E "ERROR|WARN" lv.txt; echo ---; grep "ERROR\|WARN" lv.txt; echo ---; grep -Ei "error|warn" lv.txt
ERROR one
WARN two
---
ERROR one
WARN two
---
ERROR one
WARN two
error four
```

**Always quote the pattern with single quotes.** Without quotes the shell expands `*`, `?`, `[ ]`, `$` and `!` before `grep` sees them.

**A pattern that starts with `-` is read as a flag.** Config lines such as `--etcd-servers=...` are common in static Pod manifests:

```text
REAL OUTPUT (Docker)
$ grep "--etcd-servers" man/kube-apiserver.yaml; echo exit=$?
grep: unrecognized option '--etcd-servers'
Usage: grep [OPTION]... PATTERNS [FILE]...
Try 'grep --help' for more information.
exit=2

$ grep -- "--etcd-servers" man/kube-apiserver.yaml
    - --etcd-servers=https://127.0.0.1:2379

$ grep -e "--etcd-servers" man/kube-apiserver.yaml
    - --etcd-servers=https://127.0.0.1:2379
```

`--` means "no more flags after this"; `-e PATTERN` says "the next word is the pattern".

**Exit codes.** `grep` exits `0` if it found a match, `1` if it found none, `2` on an error (such as a missing file). This lets you use it as a test:

```text
REAL OUTPUT (Docker)
$ grep -q "nosuch" lv.txt; echo exit=$?; grep -q ERROR lv.txt; echo exit=$?; grep ERROR /nonexistent; echo exit=$?
exit=1
exit=0
grep: /nonexistent: No such file or directory
exit=2
```

A "no match" is exit code 1, which a script with `set -e` or `pipefail` treats as a failure. Write `grep ... || true` when "nothing found" is acceptable.

**`-r` does not follow symlinks it finds while walking; `-R` does.** Kubernetes puts symlinks in `/var/log/containers` (section 2.12), so this matters:

```text
REAL OUTPUT (Docker)
$ grep -r needle lnk; echo exit=$?; grep -R needle lnk
exit=1
lnk/x.log:needle in real
```

**Buffering in the middle of a pipe.** When `grep` writes to a pipe instead of a terminal, it collects output in blocks. In `tail -f app.log | grep ERROR | awk '{print $2}'` you may see nothing for a long time. Add `--line-buffered` to `grep` (`tail -f app.log | grep --line-buffered ERROR | awk ...`) to flush every line. (`awk` has `fflush()` for the same job.)

**`zgrep` for compressed logs.** Rotated logs are often gzip-compressed (`.gz`). `grep` sees compressed bytes and finds nothing. `zgrep` (and `zcat`, `zless`) decompress on the fly. It is the fix for the fourth row of the "Common mistakes" table:

```text
REAL OUTPUT (Docker)
$ grep ERROR old.log.gz; echo exit=$?; zgrep ERROR old.log.gz
exit=1
ERROR rotated line
```

(`grep` printing nothing and exiting 1 is the trap: it looks like "no errors", not like "wrong tool".)

**Under the hood.** `grep` reads the input in chunks, splits it on newlines, and runs the compiled regex on each line. It never loads the file into memory as a whole, so it is safe on multi-gigabyte logs. `-r` simply walks the directory tree and runs the same loop for every regular file.

### 2.4 `sed`: change text on the way through

**What it is.** `sed` (**s**tream **ed**itor) reads input one line at a time, applies a small script to each line, and prints the result. It does not know what YAML is. It only sees lines of characters.

**The problem it solves.** "Change `replicas: 1` to `replicas: 3` in a file", "print lines 40 to 60", "remove a line", all without opening an editor. Because it is a one-liner you can also put it in your notes and in a pipe.

**Anatomy.** A script is `ADDRESS COMMAND`. The address says which lines, the command says what to do. With no address the command runs on every line.

| Piece | Meaning | Example |
|---|---|---|
| `-n` | do not print every line automatically | `sed -n '8p' d.yaml` |
| `p` | print the line (use with `-n`, otherwise lines print twice) | `sed -n '/image:/p' d.yaml` |
| `N` / `N,M` / `$` | line number / range / last line | `sed -n '7,9p'` |
| `/re/` | lines matching a regex | `sed -n '/^spec:/,/^  selector:/p'` (from the first match to the second) |
| `d` | delete the line | `sed '/ports:/,$d' d.yaml` (delete from `ports:` to the end) |
| `s/old/new/flags` | substitute | `sed 's/web/api/g'` |
| `-E` | use ERE regex (same as in `grep -E`) | `sed -E 's/(image: )(.*):(.*)/\1\2:1.27.3/'` |
| `-i` | edit the file **in place** | `sed -i 's/a/b/' f` |
| `-i.bak` | edit in place and keep the original as `f.bak` | `sed -i.bak 's/a/b/' f` |

Flags of `s`: `g` replace every match in the line (default is only the first), a number (`s/a/b/2`) replace the 2nd match, `I` ignore case, `p` print the line if a replacement happened (use with `-n`). The delimiter can be any character, so use `|` when the text contains slashes: `s|nginx:1.27|registry.example.com/nginx:1.27|`. In the replacement `&` means "the whole match" and `\1`, `\2` mean the groups captured by `( )`.

The sample file `d.yaml` used below is the 21-line Deployment printed in section 4.2 (without the comments): `replicas: 1` is on line 8 and `image: nginx:1.27` on line 19.

```text
REAL OUTPUT (Docker)
$ sed -n "8p" d.yaml
  replicas: 1

$ sed -n "7,9p" d.yaml
spec:
  replicas: 1
  selector:

$ sed -n "/image:/p" d.yaml
        image: nginx:1.27

$ sed -n "/^spec:/,/^  selector:/p" d.yaml
spec:
  replicas: 1
  selector:

$ sed "s|nginx:1.27|registry.example.com/nginx:1.27|" d.yaml | grep image:
        image: registry.example.com/nginx:1.27

$ sed -E "s/(image: )(.*):(.*)/\1\2:1.27.3/" d.yaml | grep image:
        image: nginx:1.27.3

$ sed "s/web/api/" d.yaml | grep -n api
1:apiVersion: apps/v1
4:  name: api
6:    app: api
11:      app: api
15:        app: api
18:      - name: api
```

Look at the last result. `s/web/api/` (no `g`) replaced the first `web` on **every** line that had one: the Deployment name, three labels and the container name. (Line 1 is listed only because `apiVersion` already contains the letters "api".) The substitution is applied **per line**, and it matches the text anywhere in the line. That is what makes `sed -i` dangerous: it does not know that `name: web` is the thing you meant and `app: web` is not.

**Preview before you edit.** Never start with `-i`. The safe loop is:

1. Run `sed -n 's/.../.../p' file` (prints only the lines that **would** change).
2. Run `sed 's/.../.../' file | diff -u file -` (shows the exact diff).
3. Only then add `-i.bak` and run it for real, or redirect to a new file.

```text
REAL OUTPUT (Docker)
$ sed -n "s/^  replicas: 1$/  replicas: 3/p" d.yaml
  replicas: 3

$ sed "s/web/api/" d.yaml | diff -u d.yaml - | head -n 20
--- d.yaml	2026-10-27 07:20:11.883049151 +0000
+++ -	2026-10-27 07:20:11.891901220 +0000
@@ -1,21 +1,21 @@
 apiVersion: apps/v1
 kind: Deployment
 metadata:
-  name: web
+  name: api
   labels:
-    app: web
+    app: api
 spec:
   replicas: 1
   selector:
     matchLabels:
-      app: web
+      app: api
   template:
     metadata:
       labels:
```

**Anchor the regex.** The entry's example `sed -i 's/replicas: 1/replicas: 3/' d.yaml` is correct for a file that has `replicas: 1`. It silently produces `replicas: 30` for a file that has `replicas: 10`, because `replicas: 1` is a prefix of `replicas: 10`. `^` and `$` pin the pattern to the whole line:

```text
REAL OUTPUT (Docker)
$ grep -n replicas d10.yaml; sed "s/replicas: 1/replicas: 3/" d10.yaml | grep replicas
8:  replicas: 10
  replicas: 30

$ sed "s/^  replicas: 1$/  replicas: 3/" d10.yaml | grep replicas
  replicas: 10
```

The second command changed nothing, which is correct: there is no line that is exactly `  replicas: 1`.

**In-place edits and backups.** `-i` writes the result back to the file. `-i.bak` first saves the original as `d.yaml.bak` (the suffix is glued to `-i`, no space). Then you can compare:

```text
REAL OUTPUT (Docker)
$ sed -i.bak "s/^  replicas: 1$/  replicas: 3/" e.yaml; ls e.yaml*; diff -u e.yaml.bak e.yaml
e.yaml
e.yaml.bak
--- e.yaml.bak	2026-10-27 07:20:11.891515133 +0000
+++ e.yaml	2026-10-27 07:20:11.892761435 +0000
@@ -5,7 +5,7 @@
   labels:
     app: web
 spec:
-  replicas: 1
+  replicas: 3
   selector:
     matchLabels:
       app: web
```

Traps with `-i`:

- **`-i` together with `-n` and `p` keeps only the printed lines.** `sed -i -n '/b/p' t.txt` turned a three-line file `a b c` into just `b`. Use `-n ... p` only to preview, never with `-i`.
- **The unanchored pattern deletes the indent.** This is the failure in the Break-fix lab: a pattern like `s/ *image:/image:/` matches the leading spaces too and removes them.

```text
REAL OUTPUT (Docker)
$ sed -i "s/ *image:/image:/" bad.yaml; diff -u d.yaml bad.yaml
--- d.yaml	2026-10-27 07:20:11.883049151 +0000
+++ bad.yaml	2026-10-27 07:20:11.895240995 +0000
@@ -16,6 +16,6 @@
     spec:
       containers:
       - name: web
-        image: nginx:1.27
+image: nginx:1.27
         ports:
         - containerPort: 80
```

- **`sed -i` replaces the file, it does not rewrite it.** GNU `sed -i` writes a new temporary file in the same directory and renames it over the old one. The new file has a new inode number, hard links are broken, and a **symlink is replaced by a regular file** unless you add `--follow-symlinks`:

```text
REAL OUTPUT (Docker)
$ ls -l link.yaml; sed -i "s/1/2/" link.yaml; ls -l link.yaml; cat target.yaml
lrwxrwxrwx 1 root root 11 Oct 27 07:23 link.yaml -> target.yaml
-rw-r--r-- 1 root root 5 Oct 27 07:23 link.yaml     <- the link is now a regular file
x: 1                                                  <- the real target was not edited

$ sed -i --follow-symlinks "s/1/2/" link.yaml; ls -l link.yaml; cat target.yaml
lrwxrwxrwx 1 root root 11 Oct 27 07:23 link.yaml -> target.yaml
x: 2
```

- **macOS `sed` is different.** BSD `sed -i` needs an argument (`sed -i '' ...`). The exam host and the labs are Linux (GNU sed), so the commands here are GNU commands. If you practise on a Mac, use a Linux VM or container.

**`sed` vs structure-aware tools.** `sed` edits text, so it can produce YAML that is no longer valid. For YAML the exam host has `yq` (listed among the tools on every SSH host; source: [tips page](https://docs.linuxfoundation.org/tc-docs/certification/tips-cka-and-ckad)), which edits the parsed document. It may re-indent list items, but the result stays valid:

```text
REAL OUTPUT (Docker, yq v4.54.1)
```

### 2.5 `awk`: work with columns

**What it is.** `awk` (named after Aho, Weinberger and Kernighan) is a tiny programming language built for tables. For every input line it splits the line into **fields** and runs your rules.

**The problem it solves.** `grep` can pick rows; it cannot say "print column 4" or "only rows where column 3 is greater than 5". `awk` can.

**Anatomy.** A program is a list of `pattern { action }` rules. The pattern is a condition; the action is what to do when it is true.

| Piece | Meaning |
|---|---|
| `$1`, `$2`, ... | field 1, field 2, ... of the current line |
| `$0` | the whole line |
| `NF` | number of fields on this line. `$NF` is the last field, `$(NF-1)` the one before |
| `NR` | the line number so far (counting all input) |
| `-F,` or `-F':'` | field separator. Default is "any run of blanks (spaces or tabs); leading blanks are ignored" |
| `-v name=value` | set a variable from the shell |
| `BEGIN { ... }` / `END { ... }` | run once before the first line / after the last line |
| no pattern | the action runs for every line |
| no action | the default action is `print $0` |
| `~` / `!~` | regex matches / does not match |
| `==`, `!=`, `<`, `>`, `&&`, `||` | comparisons and boolean logic |

```text
REAL OUTPUT (Docker)
$ printf 'name,qty,node\nweb,3,w1\ndb,1,w2\napi,5,w1\n' > t.csv

$ awk -F, "{print \$1}" t.csv
name
web
db
api

$ awk -F, "NR>1{print \$1}" t.csv                    <- NR>1 skips the header line
web
db
api

$ awk -F, "NR>1 && \$2>=3{print \$1, \$2}" t.csv     <- a condition on a column
web 3
api 5

$ awk -F, "NR>1{s+=\$2} END{print s}" t.csv         <- sum a column
9

$ awk -F, "\$1 ~ /^a/" t.csv                         <- regex match, default action prints the line
api,5,w1

$ awk -F, "{print NR, NF}" t.csv
1 3
2 3
3 3
4 3
```

(The `\$` is only there because the examples were run through a shell wrapper with double quotes. In your terminal write the program in **single quotes**, `awk -F, 'NR>1{print $1}' t.csv`, so the shell leaves `$1` alone.)

**Counting with arrays.** `awk` arrays are keyed by any string. `c[$3]++` adds one to the counter for each distinct value of field 3. The order of `for (n in c)` is unspecified, so pipe the result to `sort`:

```text
REAL OUTPUT (Docker)
$ awk -F, 'NR>1{c[$3]++} END{for(n in c) print c[n], n}' t.csv | sort -k2
2 w1
1 w2
```

**Printing.** `print $1, $2` joins with a space (the output field separator `OFS`); `print $1 $2` joins with nothing; `print $1 "/" $2` joins with a literal. `printf "%-6s %s\n", $1, $2` formats columns (`%-6s` = left-aligned in 6 characters).

**Spaces: default `awk` vs `cut`.** `cut -d' '` treats **each** space as a separator, so aligned `kubectl` columns (many spaces) give empty fields. Default `awk` treats a **run** of spaces as one separator:

```text
REAL OUTPUT (Docker)
$ echo "a b  c" | cut -d" " -f3
                                         <- empty: the second space made an empty field 3
$ echo "a b  c" | tr -s " " | cut -d" " -f3
c
$ echo "a b  c" | awk '{print $3}'
c
$ echo "a b  c" | awk -F"[ ]" '{print $3 "|" $4}'     <- [ ] means "exactly one space"
|c
```

**Numbers vs strings.** If both sides of a comparison look like numbers, `awk` compares them as numbers. If one side is a string literal, it compares as text. `10 > "9"` is false as text because `"1"` sorts before `"9"`:

```text
REAL OUTPUT (Docker)
$ printf '9\n10\n' > nn.txt
$ awk '$1>9' nn.txt; awk '$1>"9"' nn.txt
10
```

(First command: numeric, prints `10`. Second command: text comparison, prints nothing.)

**Which `awk`?** Ubuntu ships `mawk`; many other systems ship `gawk` (GNU awk). Every `awk` example in this lesson is plain POSIX awk, which both run. Avoid gawk-only functions (`gensub`, `strftime`, `asort`). Which awk the exam host has is UNVERIFIED.

**Under the hood.** `awk` reads one line, splits it with the field separator, tests each rule in order, and runs the actions of the rules that are true. Fields are strings that are converted to numbers on demand. That is why `awk` is robust for columns separated by blanks but not for "columns" that contain blanks themselves, such as `kubectl`'s `2 (5m ago)` in the RESTARTS column (section 2.11).

### 2.6 `cut`, `tr`, `column`: small helpers

**`cut`** takes columns from lines that have a **single-character** delimiter.

| Command | Result |
|---|---|
| `cut -d, -f1,3 t.csv` | fields 1 and 3 |
| `cut -d, -f2- t.csv` | field 2 to the end |
| `cut -d, --complement -f2 t.csv` | everything except field 2 |
| `cut -c1-3 t.csv` | characters 1 to 3 |

```text
REAL OUTPUT (Docker)
$ cut -d, -f1,3 t.csv
name,node
web,w1
db,w2
api,w1

$ cut -d, -f2- t.csv | head -n 2
qty,node
3,w1

$ cut -d, --complement -f2 t.csv | head -n 2
name,node
web,w1

$ cut -c1-3 t.csv
nam
web
db,
api
```

`cut` cannot treat "many spaces" as one separator. For aligned text first squeeze the spaces with `tr -s ' '` (next), or just use `awk`.

**`tr`** translates, squeezes or deletes **single characters**. It reads only stdin, never file arguments (`tr ... < file` or `cmd | tr ...`).

| Command | What it does |
|---|---|
| `tr -s ' '` | squeeze each run of spaces to one space |
| `tr -d '"'` | delete every double quote |
| `tr -d '\r'` | delete carriage returns (Windows line endings from a copy/paste) |
| `tr ' ' '\n'` | turn spaces into newlines (one word per line, ideal for `jsonpath` output) |
| `tr 'a-z' 'A-Z'` | upper-case (also `tr '[:lower:]' '[:upper:]'`) |

```text
REAL OUTPUT (Docker)
$ tr "a-z" "A-Z" <<< "web-1"
WEB-1

$ tr -d "\"" <<< "\"nginx:1.27\""
nginx:1.27

$ printf "a b c" | tr " " "\n"
a
b
c

$ printf "a\r\n" | od -c | head -n 1; printf "a\r\n" | tr -d "\r" | od -c | head -n 1
0000000   a  \r  \n
0000000   a  \n
```

**`column -t`** lines up columns so a result is readable. `-s,` sets the input separator. It is part of util-linux (package `bsdextrautils` on Ubuntu 24.04) and is **not** guaranteed on the exam host, so do not depend on it for answers (UNVERIFIED). It is for your eyes only, never for a file you will be graded on.

```text
REAL OUTPUT (Docker)
$ column -t -s, t.csv
name  qty  node
web   3    w1
db    1    w2
api   5    w1
```

### 2.7 `sort` and `uniq`: order, de-duplicate, count

**`sort`** orders lines. By default it compares text, in the order of your locale (language setting), so `10` comes before `9`.

| Flag | Meaning | Example |
|---|---|---|
| `-n` | numeric order | `sort -n` |
| `-r` | reverse | `sort -nr` (biggest first) |
| `-k F` or `-k F,F` | sort by field F | `-k2,2` means "only field 2". `-k2` means "field 2 to the end of line", which is rarely what you want |
| `-t X` | field separator (default: blank to non-blank change) | `sort -t, -k2,2nr` |
| `-u` | keep only the first of each set of equal lines (equal **keys** when you give `-k`) | `sort -u` |
| `-h` | human numbers (`300`, `1K`, `2M`, `1G`) | `sort -h` |
| `-V` | version order (`v1.2` < `v1.9` < `v1.10`) | `sort -V` |
| `-c` | do not sort, just check whether the input is sorted (exit code 1 if not) | `sort -c f` |
| `-o FILE` | write to FILE (safe even when FILE is also the input) | `sort -o f f` |
| `-s` | stable: keep the original order of equal lines | `sort -s -k2,2` |

```text
REAL OUTPUT (Docker)
$ sort n.txt; echo; sort -n n.txt; echo; sort -nr n.txt
10
100
9

9
10
100

100
10
9

$ sort -t, -k2 -n t.csv
name,qty,node
db,1,w2
web,3,w1
api,5,w1

$ sort -t, -k2,2nr t.csv
api,5,w1
web,3,w1
db,1,w2
name,qty,node

$ sort -h h.txt          (h.txt holds 1K 2M 300 1G, one per line)
300
1K
2M
1G

$ printf 'v1.9\nv1.10\nv1.2\n' | sort -V
v1.2
v1.9
v1.10

$ sort -u -k2,2 k.txt    (k.txt: "a 1", "b 1", "c 2")
a 1
c 2
```

(`sort -u -k2,2` kept one line per distinct field 2, the first one it saw.)

**Locale changes the order.** In a UTF-8 locale `sort` mixes upper and lower case; with `LC_ALL=C` it sorts by byte value (all capitals first). If a task says "sorted", the safest is whatever `sort` gives by default on the same host as the checker. Use `LC_ALL=C sort` only when you need a predictable byte order. For Kubernetes image names (lower case) the two usually agree.

```text
REAL OUTPUT (Docker, locale en_US.UTF-8 first, then C)
$ LC_ALL=en_US.UTF-8 sort c.txt | tr "\n" " "; echo; LC_ALL=C sort c.txt | tr "\n" " "
a b B C 
B C a b 
```

**`uniq`** collapses **adjacent** duplicate lines. That is the whole trick: you must `sort` first so equal lines are next to each other.

| Flag | Meaning |
|---|---|
| `-c` | prefix each line with how many times it occurred |
| `-d` | print only lines that occurred more than once |
| `-u` | print only lines that occurred exactly once |
| `-i` | ignore case |

```text
REAL OUTPUT (Docker)
$ printf 'b\na\nb\nc\na\nb\n' > w.txt
$ sort w.txt | uniq -c
      2 a
      3 b
      1 c

$ uniq -c w.txt                  <- without sort: nothing is adjacent, so nothing is collapsed
      1 b
      1 a
      1 b
      1 c
      1 a
      1 b

$ sort w.txt | uniq -d
a
b
```

**The pattern you will use all the time: `sort | uniq -c | sort -rn`.** First `sort` groups equal lines, `uniq -c` counts each group, the second `sort -rn` puts the biggest count on top. Add `| head -n 5` for "top 5":

```text
REAL OUTPUT (Docker)
$ sort w.txt | uniq -c | sort -rn
      3 b
      2 a
      1 c
```

`sort -u` gives the same set of lines as `sort | uniq` but no counts. For equal counts the order of `sort -rn` is decided by a last-resort comparison of the whole line, **reversed**. If you need a stable tie-break, give two keys:

```text
REAL OUTPUT (Docker)
$ sort ties.txt | uniq -c | sort -rn                 (ties.txt: x x y y z)
      2 y
      2 x
      1 z

$ sort ties.txt | uniq -c | sort -k1,1nr -k2
      2 x
      2 y
      1 z
```

The count printed by `uniq -c` is right-aligned with leading spaces. `awk` ignores leading blanks, so `... | uniq -c | awk '{print $2}'` is fine, but `cut -d' ' -f2` is not.

### 2.8 `find` and `xargs`: locate files, then act on them

**`find`** walks a directory tree and tests each file against conditions. It is the tool for "which log files changed in the last 5 minutes" or "which manifests are larger than 1 MiB".

Shape: `find WHERE TESTS ACTION`. If you give no action, `find` prints the path (`-print`). Tests are joined with "and" by default.

| Test / action | Meaning | Notes |
|---|---|---|
| `-name 'GLOB'` | file **name** (not the path) matches the glob | **Quote the glob**, otherwise the shell expands `*.log` in the current directory first (see the real error in section 6). `-iname` ignores case |
| `-type f` / `d` / `l` | regular file / directory / symlink | |
| `-mmin -5` | modified **less than** 5 minutes ago | `-mmin +60` = more than 60 minutes ago. `-mmin 5` = exactly 5 (rarely useful). `-mtime` is the same in days |
| `-size +1M` | bigger than 1 MiB | units: `c` bytes, `k` KiB, `M` MiB, `G` GiB. **Sizes are rounded up to whole units**, see below |
| `-maxdepth N` | go down at most N levels | give it **before** the other tests |
| `-path 'GLOB'` | the whole path matches | `-path '*/etcd/*'` |
| `-empty` | zero-length file or empty directory | |
| `-exec CMD {} \;` | run CMD once per file; `{}` is the file name | the `\;` ends the command (escaped so the shell does not eat it) |
| `-exec CMD {} +` | run CMD once with **many** files at the end | faster; `grep -l PATTERN {} +` |
| `-print0` | print names separated by NUL bytes | pair with `xargs -0` |
| `-delete` | delete matches | run with `-print` first. It is on the same level as `rm -rf` |

```text
REAL OUTPUT (Docker, a synthetic copy of the /var/log layout; the paths are shortened)
$ find /work/var/log/pods -name "*.log"
pods/kube-system_etcd-lab-control-plane_3f2a9c1e-.../etcd/0.log
pods/default_web-6c9b8d7f54-4mxpz_9d8e7f60-.../nginx/0.log

$ find /work/var/log/pods -name "*.log" -mmin -5      <- both files were just written
pods/kube-system_etcd-lab-control-plane_3f2a9c1e-.../etcd/0.log
pods/default_web-6c9b8d7f54-4mxpz_9d8e7f60-.../nginx/0.log

$ find /work/var/log/pods -mmin +60                    <- the .gz was back-dated 2 hours
pods/default_web-6c9b8d7f54-4mxpz_9d8e7f60-.../nginx/0.log.20261027-090500.gz

$ find /work/var/log/pods -type d -name "nginx"
pods/default_web-6c9b8d7f54-4mxpz_9d8e7f60-.../nginx

$ find /work/var/log/pods -name "*.log" -exec grep -l stderr {} +
pods/kube-system_etcd-lab-control-plane_3f2a9c1e-.../etcd/0.log
pods/default_web-6c9b8d7f54-4mxpz_9d8e7f60-.../nginx/0.log
```

**`-size` rounds up.** `-size +1k` means "more than 1 KiB after rounding the size **up** to whole KiB". A 200-byte file counts as 1 KiB, so it is **not** `+1k`; only an empty file is `-1k`. When you want exact limits, use bytes (`c`):

```text
REAL OUTPUT (Docker)
$ stat -c "%n %s" small.bin mid.bin empty.bin
small.bin 200
mid.bin 2000
empty.bin 0

$ find . -name "*.bin" -size -1k          <- rounded up: only the empty file is below 1 unit
./empty.bin

$ find . -name "*.bin" -size +1k          <- 2000 bytes = 2 units, more than 1
./mid.bin

$ find . -name "*.bin" -size +100c        <- bytes: exact
./small.bin
./mid.bin
```

**`-exec ... \;` vs `+`.** `-exec ls -l {} \;` starts one `ls` per file. `-exec grep -l stderr {} +` starts `grep` once with as many files as fit. For read-only checks prefer `+`. The difference is visible when the command is `echo`: `\;` runs it once per file, `+` runs it once with all the files (two files `a.log` and `b.log` here):

```text
REAL OUTPUT (Docker)
$ find . -name "*.log" -exec ls -l {} \; | awk '{print $5, $9}'
2 ./a.log
3 ./b.log

$ find . -name "*.log" -exec echo run {} \;
run ./a.log
run ./b.log

$ find . -name "*.log" -exec echo run {} +
run ./a.log ./b.log
```

The first command starts `ls` twice and prints the size (field 5) and name (field 9) of each file. Use `\;` when the command accepts only one file per run (`{}` may then appear anywhere in the command); use `+` when it accepts many (`{}` must be the last argument before `+`).

**`find /` is slow and noisy.** Give the narrowest starting directory (`/var/log/pods`, not `/`). As a normal user, `find` prints `Permission denied` for directories you cannot read; add `2>/dev/null` or use `sudo`. `/var/log/pods` and `/etc/kubernetes/manifests` are readable only by root on a real node, so use `sudo -i` first, as you do on the exam (`sudo -i` gives elevated privileges on any host; source: [tips page](https://docs.linuxfoundation.org/tc-docs/certification/tips-cka-and-ckad)).

**`xargs`** turns **lines of input into arguments of a command**. The problem: some commands (`rm`, `kubectl label`, `grep` file lists) take arguments, not stdin. `list | xargs cmd` runs `cmd item1 item2 ...`.

| Flag | Meaning |
|---|---|
| `-n N` | give the command at most N arguments per run. `-n1` = one run per item |
| `-I{}` | replace `{}` in the command with one input **line**. Implies one run per line, and splits only on newlines |
| `-0` | input items are separated by NUL bytes (pair with `find -print0`) |
| `-d '\n'` | (GNU) items are separated by newlines only; spaces and quotes are not special |
| `-r` | do not run the command when the input is empty (GNU runs it once by default!) |
| `-P N` | run up to N commands in parallel |
| `-t` | print each command to stderr before running it |

```text
REAL OUTPUT (Docker)
$ printf "a\nb\nc\n" | xargs -I{} echo kubectl label pod {} tier=web
kubectl label pod a tier=web
kubectl label pod b tier=web
kubectl label pod c tier=web

$ printf "a\nb\nc\n" | xargs -n2 echo
a b
c

$ xargs echo hi < /dev/null; echo ---; xargs -r echo hi < /dev/null; echo done
hi                              <- ran once with no input (GNU default)
---
done                            <- -r skipped the run

$ printf "a\nb\n" | xargs -t -I{} echo run {}
echo run a
run a
echo run b
run b
```

**Preview with `echo`.** The first command above is the standard safety habit: put `echo` in front of the real command, check the commands it would run, then remove `echo`. With `kubectl` that is `... | xargs -I{} echo kubectl label {} tier=web`.

**Aliases and shell functions are invisible to `xargs`.** `xargs` starts the program itself; it does not go through your interactive shell, so `alias k=kubectl` does not apply. The same is true for `sh -c '...'`, `watch` (it runs its command through a fresh `sh -c`) and `ssh host cmd` (the remote shell has never seen your alias). Always write `kubectl` in full inside `xargs`. The preview with `echo` hides this mistake, because `echo` is a real program and only prints the word `k`. Shown here with a shell function named `k` (an alias behaves the same way):

```text
REAL OUTPUT (Docker)
$ k() { echo "k called: $*"; }
$ k hi
k called: hi
$ printf "a\nb\n" | xargs -I{} k label {}; echo exit=$?
xargs: k: No such file or directory
exit=127
```

`127` is the "command not found" status. `k` works when you type it (first command) and is not found under `xargs` (second command). If you wrap the call in `bash -c`, the function is still not defined in the new shell (it prints `k: command not found` once per item and `xargs` exits `123`).

**The default delimiter trap.** By default `xargs` splits on **any blank**, and it also interprets quotes and backslashes. A file named `my config.yaml` becomes two arguments, `my` and `config.yaml`. Names with a newline in them break even `-d '\n'`. The safe pair is `find ... -print0 | xargs -0 ...`:

```text
REAL OUTPUT (Docker; the directory holds "my config.yaml", "plain.yaml" and a file whose name contains a newline)
$ find . -name "*.yaml" | xargs ls -1
ls: cannot access './my': No such file or directory
ls: cannot access 'config.yaml': No such file or directory
ls: cannot access './two': No such file or directory
ls: cannot access 'lines.yaml': No such file or directory
./plain.yaml

$ find . -name "*.yaml" -print0 | xargs -0 -n1 echo | wc -l       <- 3 files, but echo adds the newline inside the odd name too
4

$ printf "my config.yaml\nplain.yaml\n" | xargs -d "\n" -n1 echo "file:"
file: my config.yaml
file: plain.yaml
```

(The `4` is right: it counts output lines, and the odd name contains one newline. `-0` kept the three names intact; the plain pipe split them into five wrong pieces.)

**Kubernetes object names are safe.** A Pod, node or namespace name is a DNS name (lower-case letters, digits, `-` and `.`), so it never contains a space. Plain `xargs` is fine for `k get ... -o name`. The delimiter problem hits **file names**, label values and free text.

**Exit status.** `xargs` exits `123` if any of its commands failed, and it keeps running the rest of the items:

```text
REAL OUTPUT (Docker)
$ printf "a\nb\nc\n" | xargs -I{} sh -c "test {} != b && echo ok {}"; echo exit=$?
ok a
ok c
exit=123
```

**When not to use `xargs` with `kubectl`.** If kubectl can select the objects itself, let it: `k label pods --all tier=web` or `k label pods -l app=web tier=web` is one API call instead of N process starts. Use `xargs` when the list comes from a text filter that kubectl cannot express (for example "all Pods that are not Running").

### 2.9 `diff -u` and `vimdiff`: see what changed

**`diff`** compares two files line by line and prints the differences. **`-u`** (unified format) is the one everybody reads, and it is the format `git diff` and `kubectl diff` use.

How to read it:

- `--- a` and `+++ b` name the old and new file.
- `@@ -5,7 +5,7 @@` means: in the old file starting at line 5 for 7 lines, in the new file starting at line 5 for 7 lines.
- A line starting with `-` exists only in the old file, `+` only in the new file, and a space is unchanged context (3 lines by default).

Exit codes: `0` identical, `1` different, `2` trouble (missing file). So `diff -q a b` is a quick "same or not" test.

```text
REAL OUTPUT (Docker)
$ printf 'a\nb\nc\n' > one.txt; printf 'a\nB\nc\nd\n' > two.txt

$ diff -u one.txt two.txt; echo exit=$?
--- one.txt	2026-10-27 07:20:51.674821580 +0000
+++ two.txt	2026-10-27 07:20:51.674821580 +0000
@@ -1,3 +1,4 @@
 a
-b
+B
 c
+d
exit=1

$ diff -q one.txt one.txt; echo exit=$?
exit=0
```

More forms you will use:

| Command | Use |
|---|---|
| `diff -u old new` | the standard view |
| `diff -r dirA dirB` | compare two directories (also lists "Only in ..." files) |
| `diff -y -W 30 a b` | side-by-side; `|` changed, `>` added, `<` removed |
| `diff <(cmd1) <(cmd2)` | compare the output of two commands without temp files (process substitution, Bash) |
| `diff -w a b` | ignore all white space. **Do not use it when you hunt indentation errors in YAML**: the indent is the bug |

```text
REAL OUTPUT (Docker)
$ diff -y -W 30 one.txt two.txt
a		a
b	      |	B
c		c
	      >	d

$ diff -r da db
diff -r da/x db/x
1c1
< 1
---
> 2
Only in db: y
```

**`vimdiff`** opens the two files side by side in Vim, with the differences highlighted and unchanged blocks folded. It lets you move changes between the files with two keys. Whether `vim`/`vimdiff` exist on the exam host is UNVERIFIED (the tools list on the [tips page](https://docs.linuxfoundation.org/tc-docs/certification/tips-cka-and-ckad) names only `kubectl`, `yq`, `curl`, `wget` and `man`), so learn `diff -u` first and treat `vimdiff` as a bonus.

| Key (inside `vimdiff a b`) | Action |
|---|---|
| `]c` / `[c` | jump to next / previous difference |
| `do` | **d**iff **o**btain: pull the other file's version of this change into the current file |
| `dp` | **d**iff **p**ut: push this file's version into the other file |
| `Ctrl+w w` | switch between the two windows |
| `:diffupdate` | re-compute the highlighting after you edit |
| `:wqa` / `:qa!` | save all and quit / quit without saving |

**Related but different: `kubectl diff`.** `k diff -f d.yaml` compares your file with the **live object** in the cluster (and exits `1` when they differ). `diff` compares two **files**. Use `k diff` before an `apply`; use `diff -u` to review what your `sed` did to a file.

### 2.10 Regular expressions for Kubernetes text

You already know the pieces from 2.3. These are the patterns that come up again and again.

**Pod names with hash suffixes.** Controllers add generated parts to the names of the Pods they create:

| Created by | Pod name shape | Example |
|---|---|---|
| Deployment | `<deployment>-<replicaset-hash>-<5 characters>` | `web-6c9b8d7f54-4mxpz` |
| StatefulSet | `<name>-<ordinal>` | `web-0` |
| DaemonSet, Job | `<name>-<5 characters>` | `calico-node-9k8wz` |
| Static Pod | `<name>-<node name>` | `etcd-lab-control-plane` |

The ReplicaSet hash is derived from the Pod template and is usually 8 to 10 characters; the Pod suffix is 5 characters. Both are lower-case letters and digits. A tight regex for "Pods of Deployment `web`":

```text
REAL OUTPUT (Docker; names.txt holds five names)
$ cat names.txt
web-6c9b8d7f54-4mxpz
web-api-x7k2p
webhook-5d8f6b7c9-8vjwx
web-0
web-dev-6c9b8d7f54-q8t7d

$ grep web names.txt                                         <- too loose: everything matches
web-6c9b8d7f54-4mxpz
web-api-x7k2p
webhook-5d8f6b7c9-8vjwx
web-0
web-dev-6c9b8d7f54-q8t7d

$ grep -E "^web-[a-z0-9]+-[a-z0-9]{5}$" names.txt            <- anchored, but also matches the DaemonSet pod web-api-x7k2p
web-6c9b8d7f54-4mxpz
web-api-x7k2p

$ grep -E "^web-[a-z0-9]{8,10}-[a-z0-9]{5}$" names.txt       <- add the hash length: only the Deployment pod
web-6c9b8d7f54-4mxpz

$ grep -E "^web-[0-9]+$" names.txt                           <- StatefulSet ordinals
web-0
```

Name matching by regex is a last resort. Because `web-api-x7k2p` can look like a Deployment Pod, prefer labels when you can: `k get pods -l app=web`. The `{8,10}` hash length is the usual range, not a guarantee (UNVERIFIED, see section 11).

**IP addresses.** Match four groups of 1-3 digits separated by **escaped** dots. The unescaped dot is the classic mistake: `.` means "any character".

```text
REAL OUTPUT (Docker; ips.txt holds 10.96.0.1, 10.96.0.10, 10x96y0z1, 110.96.0.1)
$ grep "10.96.0.1" ips.txt                    <- dots are wildcards, and the match can be inside a longer address
10.96.0.1
10.96.0.10
10x96y0z1
110.96.0.1

$ grep "10\.96\.0\.1" ips.txt                 <- dots escaped, still matches inside longer addresses
10.96.0.1
10.96.0.10
110.96.0.1

$ grep -w "10\.96\.0\.1" ips.txt              <- -w: must be a whole word
10.96.0.1

$ grep -E "^10\.96\.0\.1$" ips.txt            <- anchors: the whole line
10.96.0.1
```

To **extract** IPs and ports from text use `-o`:

```text
REAL OUTPUT (Docker)
$ echo "10.96.0.1:443 and 172.18.0.3:2379" | grep -oE "([0-9]{1,3}\.){3}[0-9]{1,3}:[0-9]{1,5}"
10.96.0.1:443
172.18.0.3:2379

$ echo "kube-apiserver --secure-port=6443 --etcd-servers=https://127.0.0.1:2379" | grep -oE "[a-z-]+=[^ ]+"
--secure-port=6443
--etcd-servers=https://127.0.0.1:2379

$ echo "--secure-port=6443" | grep -oE "[0-9]+$"
6443
```

`([0-9]{1,3}\.){3}[0-9]{1,3}` also matches `999.999.999.999`. It is an extractor, not a validator, and that is enough for log reading.

### 2.11 `kubectl get` tables vs `-o jsonpath`

**The problem.** The human table from `kubectl get` is built for eyes. Its columns are separated by runs of spaces, the set of columns changes with flags, and some cells contain spaces. Parsing it with `awk` works when you know the exact shape and breaks quietly otherwise. `-o jsonpath` (and `-o custom-columns`) ask the API for exactly the fields you name, so the output does not shift. Official reference: [JSONPath support](https://kubernetes.io/docs/reference/kubectl/jsonpath/).

**Column positions of `k get pods -A -o wide --no-headers`** (this is what to verify on your cluster; the shape below is what the lesson assumes, see section 11):

| `awk` field | Column | Value |
|---|---|---|
| `$1` | NAMESPACE | `kube-system` |
| `$2` | NAME | `coredns-7d764666f9-4kq8j` |
| `$3` | READY | `1/1` |
| `$4` | STATUS | `Running` |
| `$5` | RESTARTS | `0`, **or** `2 (5m ago)` which is three fields |
| `$6` | AGE | `3d` |
| `$7` | IP | `192.168.0.3` |
| `$8` | NODE | `lab-control-plane` |
| `$9` | NOMINATED NODE | `<none>` |
| `$10` | READINESS GATES | `<none>` |

Without `-A` the NAMESPACE column is missing and every number above drops by one (`STATUS` is `$3`). With `--show-labels` an extra LABELS column is appended at the end.

**Why parsing the table breaks.** Two things shift the fields:

1. `-A` adds the NAMESPACE column in front. An `awk '{print $3}'` written for `k get pods` prints READY, not STATUS.
2. When a container has restarted, RESTARTS is printed as `2 (5m ago)`: one cell with two spaces, which `awk` sees as three fields (`2`, `(5m`, `ago)`). Every column to the right of it moves by two.

The shape of the table with a restarting Pod, trimmed:

```text
EXPECTED OUTPUT (not captured)
$ k get pods -A -o wide --no-headers
kube-system  coredns-7d764666f9-4kq8j     1/1  Running           0            3d  192.168.0.3  lab-control-plane  <none>  <none>
kube-system  calico-node-9k8wz              1/1  Running           2 (5m ago)   3d  172.18.0.2  lab-worker         <none>  <none>
lab-t102     crash-7f9c5b6d8c-2hdks       0/1  CrashLoopBackOff  4 (30s ago)  2m  192.168.1.6  lab-worker         <none>  <none>
...
```

On the `calico-node` row the text `2 (5m ago)` takes three fields, so `$6` is `(5m`, `$8` is `3d` (the AGE) and NODE has moved to `$10`. A hand-written 8-row sample with this shape printed `(5m` for `awk '{print $6}'` and `3d` for `$8` on that row (section 3). Two fixes:

- **Count from the right.** The last two columns (NOMINATED NODE, READINESS GATES) are always one word each, so NODE is `$(NF-2)` on every row: `awk '{print $(NF-2)}'`. This works only with exactly this column set (no `--show-labels`).
- **Ask for the field.** `-o jsonpath` or `-o custom-columns` never shift.

**`-o jsonpath` in 60 seconds.** The template is text with `{ ... }` expressions:

| Expression | Meaning |
|---|---|
| `{.metadata.name}` | one field of one object |
| `{.items[*].metadata.name}` | the field of every item, joined by spaces on **one line** |
| `{range .items[*]}{.metadata.name}{"\n"}{end}` | loop: one line per item. `{"\n"}` and `{"\t"}` print a newline / tab |
| `{.items[?(@.status.phase!="Running")].metadata.name}` | filter: items whose phase is not Running |
| `{.items[0].metadata.name}` | the first item only |

Use single quotes around the template so the shell leaves `$`, `"` and `{}` alone. jsonpath has no sorting and no counting; combine it with `sort`, `uniq`, `wc` or use `--sort-by=.metadata.name` on the `get`.

**`-o custom-columns`** is a table you design: `-o custom-columns=NS:.metadata.namespace,NAME:.metadata.name,NODE:.spec.nodeName`. Add `--no-headers` to drop the header. Its cells are plain fields, so `awk` and `sort` work on it without surprises (except for values that themselves contain spaces).

**`-o name`** prints `pod/web-6c9b8d7f54-4mxpz`. That form can be passed straight back to kubectl (`k label pod/web-... x=y`), which is why it is the usual input for `xargs`.

When to use which:

| Need | Best tool | Why |
|---|---|---|
| quick look, one-off filter | `k get ... \| awk` / `grep` | fastest to type |
| result goes into a file that is graded | `-o jsonpath` or `-o custom-columns` | columns cannot shift |
| names to feed another command | `-o name` | directly usable |
| nested or list fields (`containers[*].image`) | `-o jsonpath` | the table does not show them |
| sort by a field | `--sort-by=...` | built in |

The next sections show every `awk`-on-table example together with its jsonpath twin. The outputs of cluster commands are in section 5 and the labs.

### 2.12 Reading `/var/log/pods`, `/var/log/containers` and `/etc/kubernetes/manifests`

These are the three places on a **node** where Kubernetes leaves text. You read them with `grep`, `find`, `tail` and `awk`. You need `sudo -i` on a real node.

**`/var/log/pods/<namespace>_<pod-name>_<pod-uid>/<container-name>/<restart-count>.log`**

The kubelet (the node agent) tells the container runtime to write each container's stdout and stderr here. `0.log` is the first run of the container, `1.log` is the log after the first restart. Rotated files get a timestamp suffix, and the older ones may be compressed to `.gz`. The exact layout under containerd 2.x is something to confirm on your node (section 11).

**`/var/log/containers/<pod>_<namespace>_<container>-<container-id>.log`**

A flat directory of **symlinks**, one per container, pointing into `/var/log/pods/...`. Log shippers read this directory. Because they are symlinks, `grep -r` finds nothing and `grep -R` works (2.3).

**The line format (CRI log format).** Each line is `TIMESTAMP STREAM TAG MESSAGE`:

```text
2026-10-27T10:15:01.223456789Z stderr F {"level":"warn","msg":"slow fdatasync"}
```

`STREAM` is `stdout` or `stderr`. `TAG` is `F` (a full line) or `P` (a partial line: a long line split in pieces). So `awk '$2=="stderr"'` keeps only error-stream lines:

```text
REAL OUTPUT (Docker, a synthetic copy of the layout)
$ awk '$2=="stderr"{print $1}' /work/var/log/pods/*/*/0.log
2026-10-27T10:16:02.000000001Z
2026-10-27T10:15:01.223456789Z

$ find /work/var/log/containers -type l
containers/etcd-lab-control-plane_kube-system_etcd-aaaa1111.log
containers/web-6c9b8d7f54-4mxpz_default_nginx-bbbb2222.log

$ grep -r stderr /work/var/log/containers | wc -l          <- -r does not follow the links
0

$ grep -R stderr /work/var/log/containers | cut -d: -f1
containers/etcd-lab-control-plane_kube-system_etcd-aaaa1111.log
containers/web-6c9b8d7f54-4mxpz_default_nginx-bbbb2222.log

$ zgrep -h old /work/var/log/pods/*/nginx/0.log.*.gz       <- the rotated, compressed file
2026-10-27T09:00:00.000000001Z stdout F old line
```

Section 5 lists the same paths on a kind node (expected output, not captured).

**`/etc/kubernetes/manifests`** holds the **static Pod** manifests (control-plane components on a kubeadm cluster: `etcd.yaml`, `kube-apiserver.yaml`, `kube-controller-manager.yaml`, `kube-scheduler.yaml`). The kubelet watches the directory and runs whatever is described there, with no API server involved. That makes `grep` the fastest way to ask "which image, which flag, which port":

```text
REAL OUTPUT (Docker, two small sample manifests)
$ grep -rn image: man
man/etcd.yaml:7:    image: registry.k8s.io/etcd:3.7.0-0
man/kube-apiserver.yaml:7:    image: registry.k8s.io/kube-apiserver:v1.37.0

$ grep -rh image: man | awk '{print $2}' | sort -u
registry.k8s.io/etcd:3.7.0-0
registry.k8s.io/kube-apiserver:v1.37.0

$ grep -rn "service-cluster-ip-range" man
man/kube-apiserver.yaml:6:    - --service-cluster-ip-range=10.96.0.0/16

$ grep -r --include="*.yaml" -l "etcd" man
man/etcd.yaml
man/kube-apiserver.yaml
```

`grep -rn image:` does not match `imagePullPolicy:` because the pattern needs the colon directly after `image`.

**The kubelet journal.** The kubelet is a systemd service, so its log is in the journal, not in a file: `journalctl -u kubelet --no-pager | grep -iE 'error|fail'`, `journalctl -u kubelet -p err -n 50` (last 50 lines of priority "error" or worse), `journalctl -u kubelet --since "10 min ago"`. Lab 2 filters such output.

### 2.13 Saving exact answers: `> /opt/answer.txt` and `cat -A`

When a task says "write X to `/opt/answer.txt`", the grader reads the file. Anything extra on the screen is irrelevant; anything extra in the file can fail you.

- `>` creates or **overwrites** the file. `>>` appends. Run your pipeline without `>` first, look at the result, then add `> file`.
- **The redirection is done by your shell, before the command starts.** `sudo cmd > /opt/x` fails with `Permission denied` when `/opt` is root-only, because your shell (not sudo) opens the file. Use `cmd | sudo tee /opt/x >/dev/null`, or open a root shell with `sudo -i` first.
- **stdout only.** `>` captures stdout. Error messages go to stderr and stay on the screen. `2>&1` would put them in the file; do not add it unless asked.
- **Check the bytes with `cat -A`.** It shows tabs as `^I`, carriage returns as `^M` and **marks the end of every line with `$`**:

```text
REAL OUTPUT (Docker)
$ cat -A ok.txt            <- "web" + newline
web$
$ cat -A sp.txt            <- a trailing space
web $
$ cat -A nonl2.txt         <- no final newline: no $ at all
web
$ cat -A crlf.txt          <- Windows line ending
web^M$
$ cat -A tab.txt
a^Ib$

$ echo "x y" | awk '{print $1}' > o1.txt; echo "x y" | awk '{print $1, ""}' > o2.txt; cat -A o1.txt o2.txt
x$
x $
```

- A file should normally end with exactly one newline. `echo "text"` and `printf '%s\n' text` do that; `echo -n` and `printf 'text'` do not. A value captured by `$(...)` loses all trailing newlines, so write it back with `echo "$var"`.
- `-o jsonpath` prints **no trailing newline** after the last item. If you save a single value this way, follow it with `; echo` (or use `-o custom-columns` / `-o name`, which end with a newline).
- Do not add headers, labels, quotes or alignment (`column -t`) unless the task asks. If the task shows an example format, copy it exactly.
- The exam says nothing public about how answer files are compared (UNVERIFIED), so treat "exactly what was asked, newline-terminated, nothing else" as the rule.

A good last step for every "save to file" task:

```bash
cat -A /opt/answer.txt     # look for ^M, trailing spaces, a missing $, extra blank lines
wc -l /opt/answer.txt      # number of lines should match what you expect
```

Walkthrough:

1. `kubectl` prints one line per Pod. `--no-headers` removes the header so nothing in the data is a title.
2. `grep` is a **row** filter: it keeps or drops whole lines. Run it first so later stages see less text.
3. `awk` is a **column** picker. `$(NF-2)` counts from the right, so the two extra words in `4 (30s ago)` do not move it. Writing `$8` instead would print `2m` for the `crash` row (shown in section 6).
4. `sort` and `uniq -c` count. `uniq` only merges **neighbours**, which is why `sort` must come before it.
5. `>` writes stdout to the file. The pipeline text never touches the screen, so build and check it **without** `>` first.
6. If `kubectl` fails (wrong context, API down), the pipe still runs on empty input and writes an empty file. `ls -l` or `cat -A` on the result catches that.

### 4.1 Imperative shortcuts

| Command | What it does |
|---|---|
| `k get pods -A --no-headers \| awk '$4!="Running"{print $1,$2}'` | namespace and name of every Pod whose STATUS is not `Running`. `$4` is STATUS because `-A` put NAMESPACE in front. Columns left of RESTARTS never shift |
| `k get pods -A -o jsonpath='{range .items[?(@.status.phase!="Running")]}{.metadata.namespace} {.metadata.name}{"\n"}{end}'` | the same, with jsonpath (uses the Pod **phase**, see the note below) |
| `k get pods -A -o wide --no-headers \| awk '{print $8}' \| sort \| uniq -c > /tmp/podcount.txt` | the entry's Pods-per-node count. Correct while no Pod has a restart text; use `$(NF-2)` to be safe |
| `k get pods -A -o jsonpath='{range .items[*]}{.spec.nodeName}{"\n"}{end}' \| sort \| uniq -c` | the jsonpath twin: no column positions at all |
| `grep -rn image: /etc/kubernetes/manifests` | every image line (with file and line number) of the static Pods |
| `sed -i 's/replicas: 1/replicas: 3/' d.yaml` | the entry's one-liner. Safe only if no line says `replicas: 10`, `replicas: 11` ... Safer: `sed -i.bak 's/^  replicas: 1$/  replicas: 3/' d.yaml` |
| `find /var/log/pods -name '*.log' -mmin -5` | log files written in the last 5 minutes |
| `k get pods -o name \| xargs -I{} kubectl label {} tier=web` | label every Pod of the current namespace. Write `kubectl` in full after `xargs`: the alias `k` is not visible there (section 2.8). Often `k label pods --all tier=web` is shorter |

**Phase vs STATUS.** The STATUS column of the table is a computed word (`Running`, `CrashLoopBackOff`, `ImagePullBackOff`, `Completed`, `Terminating` ...). The jsonpath field `.status.phase` has only `Pending`, `Running`, `Succeeded`, `Failed` or `Unknown`. A Pod in `CrashLoopBackOff` or `ImagePullBackOff` has phase `Running` or `Pending`. So the two filters above are **not** identical: the awk one is "STATUS is not Running" and the jsonpath one is "phase is not Running". When a task says "not Running", look at what it means and say which you used. To get the same words as the table with jsonpath you need `.status.containerStatuses[*].state.waiting.reason`, which is long; this is a case where parsing the table is the faster answer.

**jsonpath twin for every awk-on-kubectl example (used in this lesson):**

| `awk` on the table | jsonpath / custom-columns twin |
|---|---|
| `... --no-headers \| awk '{print $2}'` (Pod names) | `k get pods -A -o jsonpath='{range .items[*]}{.metadata.name}{"\n"}{end}'` |
| `... \| awk '$4!="Running"{print $1,$2}'` | `k get pods -A -o jsonpath='{range .items[?(@.status.phase!="Running")]}{.metadata.namespace} {.metadata.name}{"\n"}{end}'` (phase, not STATUS) |
| `... -o wide --no-headers \| awk '{print $8}'` (node) | `k get pods -A -o jsonpath='{range .items[*]}{.spec.nodeName}{"\n"}{end}'` or `-o custom-columns=NODE:.spec.nodeName --no-headers` |
| `... \| awk '{print $7}'` (Pod IP) | `k get pods -A -o jsonpath='{range .items[*]}{.status.podIP}{"\n"}{end}'` |
| image column (not in the table at all) | `k get pods -A -o jsonpath='{.items[*].spec.containers[*].image}' \| tr -s ' ' '\n'` |

### 4.2 The YAML you edit with these tools

There are two files in this lesson that you edit with `sed` and compare with `diff`: a Deployment (the speed drills) and a static Pod (Lab 3).

Generate the Deployment instead of typing it:

```bash
mkdir -p ~/lab/t102 && cd ~/lab/t102
k create deploy web --image=nginx:1.27 --replicas=1 $do > d.yaml
```

`$do` expands to `--dry-run=client -o yaml`: build the object locally, print it as YAML, do not send it. The generated file has some extra lines (`strategy: {}`, `resources: {}`, `status: {}`) and sorts keys alphabetically, and it names the container after the image (`name: nginx`, not `web`). Those are normal for `$do`. Here is a clean hand-written version of the same object, with every field explained; the `sed` examples in this lesson use it:

```yaml
apiVersion: apps/v1          # API group/version of the Deployment resource
kind: Deployment             # what kind of object this is
metadata:
  name: web                  # object name; DNS-1123 label, unique within the namespace
  labels:
    app: web                 # a label on the Deployment itself (used by you for lookup, not by the controller)
spec:
  replicas: 1                # desired number of Pods; default 1; negative values are rejected; 0 stops all Pods
  selector:
    matchLabels:
      app: web               # which Pods this Deployment owns; must match template.metadata.labels
  template:                  # the Pod template: every Pod is stamped from this
    metadata:
      labels:
        app: web             # must satisfy the selector above, or the API server rejects the Deployment
    spec:
      containers:
      - name: web            # container name; unique inside the Pod
        image: nginx:1.27    # always pin a tag; ":latest" or no tag makes pulls and rollbacks unpredictable
        ports:
        - containerPort: 80  # documentation for readers and tools; it does not open or close a port
```

Where `sed` goes wrong here: `app: web` appears three times and `name: web` twice, `replicas: 1` is a prefix of `replicas: 10`, and `image:` has a deep indent that a careless `s/ *image:/image:/` deletes.

The static Pod used in Lab 3 (a Pod the kubelet runs from a file; no API server needed to start it):

```yaml
apiVersion: v1               # Pods are in the core API group
kind: Pod
metadata:
  name: web-static           # the kubelet adds the node name: the mirror Pod is "web-static-<node>"
  labels:
    app: web-static          # label on the Pod
spec:
  containers:
  - name: web                # container name
    image: nginx:1.26        # pinned tag; Lab 3 moves it to 1.27
    ports:
    - containerPort: 80      # informational, same as above
```

A static Pod is not managed by a Deployment or ReplicaSet. If you delete the **mirror Pod** with `kubectl`, the kubelet recreates it; the only way to stop it is to remove or change the file.

**Goal.** On the lab cluster, answer six questions about a small workload, saving each answer to a file and proving the file is clean. You see what each command does, what to look for in the output, and the jsonpath twin of every table-parsing step.

### Step 0: build the workload

### Step 1: look at the table before you parse it

```bash

```


Look at three things before you write any `awk`: (1) how many columns there are (9 here, because there is no NAMESPACE column without `-A`), (2) which cells hold more than one word (`4 (30s ago)`), (3) which flags you will use in the real command, since every flag changes the columns. The columns of the 10-column `-A -o wide` table are listed in section 2.11 and need to be checked once on your cluster (section 11).

Count the fields per row the way `awk` sees them. This is the fastest way to find the shifted rows:

```bash
k get pods -A -o wide --no-headers | awk '{print NF}' | sort | uniq -c
```

```text
EXPECTED OUTPUT (not captured; the idea is two groups of rows, N and M depend on your cluster)
     N 10          <- ordinary rows
     M 12          <- rows whose RESTARTS cell is "2 (5m ago)"
```

If this prints two different numbers, every column to the right of RESTARTS is in a different position on some rows. A hand-written 8-row sample gave exactly `6 10` and `2 12` (see section 3).

### Step 2: which Pods are not Running?

```bash
cd ~/lab/t102
k get pods -A --no-headers | awk '$4!="Running"{print $1,$2}'
```

`--no-headers` removes the title row, `$4` is STATUS (because `-A` adds NAMESPACE as `$1`), `{print $1,$2}` prints namespace and name. STATUS is left of RESTARTS, so the restart text cannot move it.

```text
EXPECTED OUTPUT (not captured)
lab-t102 broken
lab-t102 crash
```

The jsonpath twin (phase, not STATUS: a crash-looping Pod has phase `Running`, so it is **not** listed here, see the note in section 4.1):

```bash
k get pods -A -o jsonpath='{range .items[?(@.status.phase!="Running")]}{.metadata.namespace} {.metadata.name}{"\n"}{end}'
```

```text
EXPECTED OUTPUT (not captured)
lab-t102 broken
```

The two filters answer slightly different questions. For "Pods that are not Running" in the sense of the table word, the `awk` version is the one to use.

### Step 3: how many Pods per node? Spot the shifted column

The entry's command:

```bash
k get pods -A -o wide --no-headers | awk '{print $8}' | sort | uniq -c
```

On a row without a restart text, `$8` is NODE. On a row with `4 (30s ago)` the node name has moved two places to the right and `$8` is the AGE:

```text
EXPECTED OUTPUT (not captured; shape only, N depends on your cluster)
      1 2m                   <- AGE of the crash row, not a node
      N lab-control-plane
      N lab-worker
      N lab-worker2
```

A hand-written sample with the same shape printed `1 2m`, `1 3d`, ... for the two restarted rows. The fix is to count from the right (NODE is always the third field from the end for `-A -o wide`):

```bash
k get pods -A -o wide --no-headers | awk '{print $(NF-2)}' | sort | uniq -c > ~/lab/t102/podcount.txt
cat -A ~/lab/t102/podcount.txt
```

```text
EXPECTED OUTPUT (not captured; the counts N depend on your cluster)
      N lab-control-plane$
      N lab-worker$
      N lab-worker2$
```

Check the file with `cat -A`: each line ends with `$` and nothing else, and the count is padded with spaces by `uniq -c` (that is its normal format). The jsonpath twin has no positions to get wrong:

```bash
k get pods -A -o jsonpath='{range .items[*]}{.spec.nodeName}{"\n"}{end}' | sort | uniq -c
```

The two results should be identical. Comparing them is a good self-check. Both pipelines written out in full (`diff` prints nothing and `same` appears when they agree):

```bash
diff <(k get pods -A -o wide --no-headers | awk '{print $(NF-2)}' | sort | uniq -c) \
     <(k get pods -A -o jsonpath='{range .items[*]}{.spec.nodeName}{"\n"}{end}' | sed 's/^$/<none>/' | sort | uniq -c) \
  && echo same
```

The `sed 's/^$/<none>/'` stage handles one difference: a Pod that is not scheduled yet has no node. The table prints `<none>` for it, and jsonpath prints an empty line. Without that stage the two results would differ whenever a Pod is Pending without a node. In this workload every Pod is scheduled (a Pod stuck in `ImagePullBackOff` already has a node), so the stage changes nothing here.

## 6. Common mistakes and how to fix them

| Symptom | What you will see | Cause | Fix |
|---|---|---|---|
| `awk` prints the wrong column with `-A` | `k get pods -A --no-headers \| awk '{print $3}'` prints `1/1`, `0/1`, ... (READY) instead of the status | the NAMESPACE column shifts every field right by one | count the columns of the header, or use `-o jsonpath` / `-o custom-columns` |
| `awk` prints `2m` or `(5m` instead of a node | one row of `awk '{print $8}'` output looks like an age; the per-node count gets a bogus group such as `1 2m` | RESTARTS cell `2 (5m ago)` is three words | `awk '{print $(NF-2)}'` for `-A -o wide`, or jsonpath |
| `sed -i` broke YAML indentation | `yq` says `go-yaml load error in scanner at L11.C10: mapping values are not allowed in this context`; `k apply` says `error: error parsing STDIN: error converting YAML to JSON: yaml: line 11: mapping values are not allowed in this context` (both texts are real, see Lab 3) | the regex matched leading spaces or more lines than intended | restore from `.bak`; anchor with `^` and `$`; preview with `sed -n 's/.../.../p'` first |
| `replicas: 10` became `replicas: 30` | `grep replicas d.yaml` shows `30` | `s/replicas: 1/replicas: 3/` matches the prefix of `replicas: 10` | `s/^  replicas: 1$/  replicas: 3/` |
| `xargs` fails on names with spaces / newlines | `ls: cannot access './my': No such file or directory` and `ls: cannot access 'config.yaml'...` | default delimiter is any blank | `find ... -print0 \| xargs -0 ...` or `xargs -d '\n'` |
| `xargs` cannot run `k` | `xargs: k: No such file or directory`, exit code 127 (or `123` under `bash -c`); the `echo` preview looked fine | `k` is a shell alias, and `xargs`, `sh -c`, `watch` and `ssh` start programs without your aliases | write `kubectl` in full after `xargs` (section 2.8) |
| `grep` finds nothing in a rotated log | no output, `echo $?` prints `1`, but you know the error exists | the file is gzip-compressed (`*.log.*.gz`) | `zgrep PATTERN file.gz`, or `zcat file.gz \| grep PATTERN` |
| `grep -r` finds nothing in `/var/log/containers` | exit code 1, no lines | the entries are symlinks and `-r` does not follow them while walking | `grep -R` or search `/var/log/pods` directly |
| `uniq -c` shows every line with count 1 | `1 b`, `1 a`, `1 b` | the input was not sorted, so equal lines are not neighbours | `sort \| uniq -c` |
| `grep: unrecognized option '--etcd-servers'` | exit code 2 and the usage text | the pattern starts with `-` | `grep -- '--etcd-servers' f` or `grep -e '--etcd-servers' f` |
| `bash: /opt/answer.txt: Permission denied` with `sudo` | the file was not written | the redirection is done by your shell, not by `sudo` | `cmd \| sudo tee /opt/answer.txt >/dev/null`, or `sudo -i` first |
| the answer file fails the check although the output "looks right" | `cat -A` shows `$` missing, `^M`, extra spaces, or a header line | `echo -n`, jsonpath without trailing newline, `column -t`, `\r` in the source, or a forgotten `--no-headers` | rebuild with `--no-headers`, `tr -d '\r'`, end with one newline; check with `cat -A` and `wc -l` |
| `find . -name *.log` fails or silently finds too little | with two `.log` files in the directory: ``find: paths must precede expression: `b.log'`` then ``find: possible unquoted pattern after predicate `-name'?``, exit code 1. With exactly one `.log` file there is no error: it searches for that one name only | the unquoted glob was expanded by the shell before `find` ran | `find . -name '*.log'` |
| `-mmin -5` returns nothing although the log was written | empty output | `-5` means "less than 5 minutes ago"; the file is older, or the clock differs | `find ... -mmin -60`; check `date` and `ls -l --time-style=full-iso file` |

### 6.1 Reasoning through the four required failures

**A. `awk` prints the wrong column.** Run, in this order:

1. `k get pods -A --no-headers | head -n 3` : look at the first rows with your eyes.
2. `k get pods -A --no-headers | awk '{print NF}' | sort | uniq -c` : if you see two or more numbers, some rows have extra words.
3. `k get pods -A | head -n 1` : count the header words for the column you want.

Read it like this: one number (all rows have 8 fields) means the column positions are stable and you only miscounted. Two numbers mean a restart cell is shifting columns. Fix: count from the right with `$(NF-n)`, or stop parsing the table and use `-o jsonpath` / `-o custom-columns=...`.

**B. `sed -i` broke the YAML.** Run:

1. `diff -u file.bak file` (or against a known good copy): the changed lines start with `-` and `+`. Look for a `+` line with fewer leading spaces than the `-` line above it.
2. `yq . file` or `k apply --dry-run=client -f file`: the error names the line (for the Lab 3 file: `error: error parsing STDIN: error converting YAML to JSON: yaml: line 11: mapping values are not allowed in this context`).
3. Restore (`cp file.bak file`) and rerun with an anchored pattern, previewed first: `sed -n 's/^    image: .*/.../p' file` must print exactly the lines you intend to change, no more.

Why it happens: `sed` has no idea about YAML structure; indentation is just space characters at the start of the line. A pattern such as ` *image:` swallows them.

**C. `xargs` fails on names with spaces or newlines.** Run `printf '%s\n' ... | xargs -n1 echo | wc -l` and compare with the number of items you expected. A bigger number means items were split. Replace the separator: `-print0 | xargs -0` for `find`, or `-d '\n'` for line lists. For Kubernetes **names** this does not occur because DNS names have no spaces.

**D. `grep` shows no matches in a rotated log.** Run `ls -l /var/log/pods/*/*/` and look for `.gz`; `file path` prints `gzip compressed data` for compressed files; then `zgrep`. Exit code 1 from `grep` on a `.gz` file is not a "no error found" result, it is a wrong-tool result.

<details><summary>Hints</summary>

1. Init containers are a different field from containers (`initContainers` vs `containers`).
2. `-o jsonpath` with `[*]` puts all values on **one line** separated by spaces. `tr -s ' ' '\n'` turns them into lines.
3. An empty jsonpath result can leave an empty line; remove it with `sed '/^$/d'`. `sort -u` does the sorting and the de-duplication.

</details>

<details><summary>Solution</summary>

```bash
cd ~/lab/t102
k get pods -A -o jsonpath='{.items[*].spec.initContainers[*].image} {.items[*].spec.containers[*].image}' \
  | tr -s ' ' '\n' | sed '/^$/d' | sort -u > images.txt
cat images.txt
```

Why each stage: the two `jsonpath` expressions list the images of all init containers and then of all containers, joined by a space. `tr -s ' ' '\n'` splits that long line into one image per line (and squeezes repeated spaces). `sed '/^$/d'` deletes any empty line (the leading space becomes an empty first line when no Pod has an init container). `sort -u` sorts and removes duplicates in one step. `>` writes the result. A table-based approach cannot work here because `k get pods` has no image column at all.

</details>

**Verification** (each line prints `ok` or the command exits non-zero / prints nothing):

**Environment:** any Linux shell (linux-vm). The input is a synthetic file that the script below generates, so the answer is exact and repeatable. It mimics the layout of `journalctl -u kubelet` lines but is **not** real kubelet output.

**Setup:**

`wc -l kubelet.log` prints `189 kubelet.log`. The file has lines in random order (`shuf`), so `head` shows a mixture of `I`, `E` and `W` lines. The letter right after `kubelet[612]: ` (`E1027`, `I1027`, `W1027`) is the klog severity: **E**rror, **I**nfo, **W**arning.

**Task.** Using only `grep`, `sed`, `sort`, `uniq` and `head`, write the **5 most frequent error messages** to `~/lab/t102/top5.txt`, highest count first. Use `uniq -c` format (count, then the message). The message is the text after `kubelet.go:NNNN] ` (drop the date, host, PID and source file). Count only `E` lines.

<details><summary>Hints</summary>

1. Which field tells you the severity? Run `head -n 3 kubelet.log` and look for the letter before `1027`. `grep -E ' E[0-9]{4} '` keeps only those lines.
2. Every line has a different timestamp, so `uniq -c` would see 114 different lines. Cut everything up to and including `kubelet.go:NNNN] ` first (`sed -E 's/^.*[a-z]+\.go:[0-9]+\] //'`). Note that the first `]` in the line is the one in `kubelet[612]`, so a pattern that stops at the first `]` does not work.
3. After that the pipeline is the standard one: `sort | uniq -c | sort -rn | head -n 5`.

</details>

<details><summary>Solution</summary>

```bash
cd ~/lab/t102
grep -E 'kubelet\[[0-9]+\]: E[0-9]{4} ' kubelet.log \
  | sed -E 's/^.*[a-z]+\.go:[0-9]+\] //' \
  | sort | uniq -c | sort -rn | head -n 5 > top5.txt
cat top5.txt
```

Why each stage: `grep -E` keeps only error lines (114 of 189); the pattern is anchored on `kubelet[PID]: E1027` so a message that happens to contain " E1027 " is not counted. `sed -E` removes the variable prefix so equal messages become equal lines. `sort` makes equal lines neighbours, `uniq -c` counts, `sort -rn` puts the biggest count first, and `head -n 5` keeps five. Output on the generated file:

```text

     12 "Container probe failed" probeType="Liveness" pod="default/api-1"

```

The `grep -E` stage can also be an `awk` filter: `awk '$6 ~ /^E[0-9]+$/' kubelet.log` (field 6 is the severity word, for example `E1027`). Replace the `grep` stage with it and the rest of the pipeline stays the same.

</details>

### Lab 3 (Break-fix): a `sed` one-liner corrupted a static Pod manifest

**Environment:** kind (the control-plane node container `lab-control-plane`). Use your own throwaway static Pod, not a control-plane component, so a mistake cannot break the cluster. `nginx:1.26` is a deliberate exception to the conventions' test-image list: the lab needs an old tag to move to `nginx:1.27`.

**On the kubeadm VMs (not run, see section 11).** Do not wrap the commands in a helper such as `ssh cp1 sudo ...`: `ssh` joins its arguments into one string and the remote shell parses it a second time, so the quotes around the `sed` script are lost and `sed` fails. Do it the way the exam works instead: `ssh cp1`, then `sudo -i`, then run every `cpx ...` command below **without the `cpx` prefix**, and `exit` back to the base host before you run the `k ...` commands there (no nested ssh). The mirror Pod is named after the node, so replace `web-static-lab-control-plane` with `web-static-<control-plane node name>` (`k get nodes`).

**Setup:**

```bash

mkdir -p ~/lab/t102 && cd ~/lab/t102
cpx() { docker exec lab-control-plane "$@"; }          # kind only; on VMs see the Environment note above
cat > web-static.good.yaml <<'EOF'
apiVersion: v1
kind: Pod
metadata:
  name: web-static
  labels:
    app: web-static
spec:
  containers:
  - name: web
    image: nginx:1.26
    ports:
    - containerPort: 80
EOF
docker cp web-static.good.yaml lab-control-plane:/etc/kubernetes/manifests/web-static.yaml    # on VMs: scp it, then sudo cp
```

The kubelet runs the file and creates a **mirror Pod** (a read-only copy in the API) called `web-static-lab-control-plane` (the Pod name plus the node name). The last command prints `nginx:1.26`. Keep `cpx` defined in your shell for the whole lab.

**Fault injection** (`break.sh`; run it once, then do not read it again until you have tried):


**Task.** A colleague ran a `sed` one-liner on the control-plane node to move the static Pod `web-static` from `nginx:1.26` to `nginx:1.27`. Afterwards the Pod in namespace `default` does not run `nginx:1.27`. Make the mirror Pod `web-static-lab-control-plane` Running with image `nginx:1.27`. The manifest `/etc/kubernetes/manifests/web-static.yaml` must differ from the reference copy `/root/web-static.good.yaml` **only** in the image tag. Do not touch any other file in `/etc/kubernetes/manifests`.

<details><summary>Hints</summary>

1. You have a known-good copy. `cpx diff -u /root/web-static.good.yaml /etc/kubernetes/manifests/web-static.yaml` shows what really changed. Read the `+` lines slowly: how many spaces are in front of `image:`?
2. A static Pod manifest is read by the kubelet from disk. The Pod list can be out of date; the file on disk is the truth. Ask the YAML parser what it thinks: `cpx cat /etc/kubernetes/manifests/web-static.yaml | k apply --dry-run=client -f -` should print an error for the broken file: `error: error parsing STDIN: error converting YAML to JSON: yaml: line 11: mapping values are not allowed in this context` (this exact text was produced by a kubectl v1.37.1 client with no cluster). 3. Fix only the one line, anchored at the start of the line (`^image:`), and diff again before you trust it.

</details>

<details><summary>Solution</summary>

```bash
# 1. Find the damage: compare with the reference copy
cpx diff -u /root/web-static.good.yaml /etc/kubernetes/manifests/web-static.yaml
```

The diff shows one line removed (`-    image: nginx:1.26`, four spaces) and one added (`+image: nginx:1.27`, no spaces). The tag change is right; the leading spaces were deleted. That breaks the YAML structure: `image:` at the start of the line ends the `containers` list item, so the file is no longer a valid Pod. The cause is the unanchored `s/^ *image: .*/.../`: it matched the indentation (` *`) and the replacement did not put it back.

```bash
cpx diff -u /root/web-static.good.yaml /etc/kubernetes/manifests/web-static.yaml
```

The new pattern starts with `^image:` (the broken line has no indent, so it matches only that line) and the replacement restores four spaces. The final diff must show exactly one `-` line and one `+` line, both `image:` with four leading spaces, only the tag different.


If the Pod still shows `nginx:1.26`, wait a little longer and run the jsonpath again: the kubelet must see the file change, stop the old Pod and start the new one (with an image pull).

</details>

## 8. Exam tips

- **Build pipes left to right and look after every `|`.** Run the first stage, then add `| grep`, then `| awk`, then `| sort | uniq -c`. A wrong column is visible at the stage where it appears. Add `> file` last. Time saver: `Ctrl+R` or the up arrow, then append the next stage.
- **For anything saved to a file, prefer `-o jsonpath` or `-o custom-columns` over parsing the table**, and always finish with `cat -A file` and `wc -l file`. Bookmark the [JSONPath support page](https://kubernetes.io/docs/reference/kubectl/jsonpath/) and the [kubectl Quick Reference](https://kubernetes.io/docs/reference/kubectl/quick-reference/) (both are on kubernetes.io/docs, which the exam allows, per the [allowed-resources page](https://docs.linuxfoundation.org/tc-docs/certification/certification-resources-allowed)). The Quick Reference has copy-paste jsonpath examples for images, node IPs and sorting.
- **Traps to check before you move on:** (1) did `-A` change the column numbers? (2) any `N (T ago)` restart cells? (3) is there a header line in the file? (4) did `sed -i` have an anchor, and did you diff it? (5) is the path exactly what the task says, and did the file get created as the right user (`sudo -i` for root-only paths)?
- **`sed -i` is not undoable.** Use `-i.bak` (or `cp f ~/f.orig`) first, but never leave the backup inside `/etc/kubernetes/manifests`. For live objects use `k scale`, `k set image`, `k patch` or `k edit` instead of editing text.
- **On a node, `sudo -i` first.** `/var/log/pods` and `/etc/kubernetes/manifests` are root-only. Remember that you leave each node with `exit` back to the host `base`, nested ssh is not supported (per the [tips page](https://docs.linuxfoundation.org/tc-docs/certification/tips-cka-and-ckad)). `jq`, `tmux` and `column` are not on the tool list given there (`kubectl`, `yq`, `curl`, `wget`, `man`), so build answers from `grep`/`awk`/`sort` and `yq`/jsonpath.
- **Do not use `kubectl` output formats you have not seen on the exam cluster.** Before you rely on a column number, run `k get pods -A -o wide | head -n 2` once and count.

## 9. Quick review

1. What command prints a `kubectl` table without the header, and why is `tail -n +2` also a valid way?
   <details><summary>Answer</summary>`k get pods --no-headers` asks kubectl not to print the header. `tail -n +2` prints from line 2 on, so it drops the first line after the fact. `--no-headers` is cleaner; `tail -n +2` works for any text.</details>
2. Why does `k get pods -A --no-headers | awk '{print $3}'` print `1/1` and not the status?
   <details><summary>Answer</summary>`-A` adds the NAMESPACE column in front, so fields move one place right: `$3` is READY and STATUS is `$4`.</details>
3. What is the difference between `grep -c ERROR f` and `grep -o ERROR f | wc -l`?
   <details><summary>Answer</summary>`-c` counts the **lines** that contain a match; `-o ... | wc -l` counts the **matches**. They differ when a line has two matches.</details>
4. Which command safely previews and then applies a change of `replicas: 1` to `replicas: 3`, keeping a backup?
   <details><summary>Answer</summary>`sed -n 's/^  replicas: 1$/  replicas: 3/p' d.yaml` (must print one line), then `sed -i.bak 's/^  replicas: 1$/  replicas: 3/' d.yaml`, then `diff -u d.yaml.bak d.yaml`.</details>
5. Why must `sort` come before `uniq -c`, and what does `sort | uniq -c | sort -rn` give?
   <details><summary>Answer</summary>`uniq` only collapses neighbouring equal lines. `sort` makes equal lines neighbours. The pipeline counts each distinct line and lists the most frequent first.</details>
6. How do you list the files in `/var/log/pods` that were modified in the last 5 minutes, and what does `+5` mean instead of `-5`?
   <details><summary>Answer</summary>`find /var/log/pods -name '*.log' -mmin -5`. `-5` = less than 5 minutes ago, `+5` = more than 5 minutes ago.</details>
7. A `find` result contains file names with spaces. How do you pass them safely to `grep -l`?
   <details><summary>Answer</summary>`find ... -print0 | xargs -0 grep -l PATTERN` (or `find ... -exec grep -l PATTERN {} +`, which needs no pipe).</details>
8. `grep` returns nothing for a pattern you know is in the rotated log `0.log.20261027-090500.gz`. Why, and what do you run?
   <details><summary>Answer</summary>The file is gzip-compressed, so the text is not there as text. Use `zgrep PATTERN file.gz` (or `zcat file.gz | grep PATTERN`).</details>
9. Why is `-o jsonpath` preferred over `awk` on the table for a result that is graded?
   <details><summary>Answer</summary>jsonpath asks for exact fields, so the output does not depend on the number of columns, `-A`, `-o wide`, or cells with spaces such as `2 (5m ago)`.</details>
10. You ran `sudo kubectl get pods > /opt/answer.txt` and got `Permission denied`. Why, and what is the fix?
    <details><summary>Answer</summary>The shell opens `/opt/answer.txt` for the redirection before `sudo` runs, as your user. Use `sudo -i` and run the command as root, or `... | sudo tee /opt/answer.txt > /dev/null`.</details>
